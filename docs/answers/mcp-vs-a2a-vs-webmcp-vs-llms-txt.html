MCP vs A2A vs WebMCP vs llms.txt

Reviewed 2026-09-05Current specs checkedCC BY 4.0
They solve different layers. MCP is a protocol for connecting AI applications to tools/resources; A2A is an agent-to-agent interaction standard; WebMCP exposes tools from a web page runtime; llms.txt is a text-oriented discovery/routing convention for useful site content. A site may legitimately expose several of them at once.
SurfacePrimary roleWhere it livesWhat discovery alone proves
MCPTool/resource/context interoperability between an AI client and an MCP server.Server endpoint / protocol runtime.Metadata can advertise a server; runtime verification is separate.
A2ACommunication and task collaboration between independent agents.A2A server plus Agent Card, including the standard well-known discovery path.A valid Agent Card describes identity/capabilities/interfaces; it is not itself authorization to act.
WebMCPExpose web-application functionality as browser-visible tools backed by page logic.Browser/page JavaScript runtime.Static HTTP crawling may not observe a runtime-only tool surface.
llms.txtProvide a concise text map of useful site content for LLM/agent retrieval.Plain-text web resource, commonly /llms.txt.It routes readers to content; it is not a tool protocol or permission model.

Current protocol facts

The MCP 2026-07-28 generation introduced a stateless core and authorization hardening. A2A currently publishes version 1.0.0 and standardizes Agent Card discovery at /.well-known/agent-card.json. WebMCP is an evolving browser API proposal for exposing page functionality as structured tools.

The important architectural consequence is that “agent-ready” does not imply one file or one protocol. Content retrieval, backend tools, remote agents and browser-local tools can coexist.

ARWP's position

ARWP does not replace these protocols. The Resolver observes and normalizes multiple discovery ecosystems, preserves their source authority and chooses an interface for a specific intent.
