What is an agentic web resolver?

Reviewed 2026-09-05Project-defined termCC BY 4.0
An agentic web resolver discovers the machine- and agent-facing interfaces a website actually exposes, preserves where each observation came from, reports conflicts, and selects an interface for a concrete intent.

Why it is useful

A modern site may expose ordinary HTML, Markdown negotiation, llms.txt, OpenAPI, API Catalog metadata, Agent Skills, MCP, A2A or browser-runtime tools. These surfaces are not interchangeable. A resolver lets a client combine them without requiring every publisher to adopt one universal manifest.

ARWP's resolver model keeps source authority and fallbacks visible. It can answer questions such as “which interface should I use to read?”, “is there a structured search surface?”, or “does the site advertise an agent endpoint?” without silently converting one protocol into another.

What it should preserve

  • canonical site identity and target scope;
  • the source and authority of each observation;
  • conflicting declarations instead of overwriting them;
  • selected interface plus rejected/alternate candidates;
  • what static evidence can and cannot prove.

What it is not

A resolver is not a permission layer, a trust score, an SEO score, or proof that an advertised runtime will successfully execute a task.
