Future Search · governed experiments

Prepare the site model before the feature exists.

ARWP separates current Search requirements from future-ready machine semantics. A useful open-web mechanism does not need to be a documented ranking factor to be worth testing — but every experiment must remain truthful, bounded, reversible and measurable.

Current platform layer

Crawl/index eligibility, canonical URLs, content quality, identity, crawler policy and current Search/AI features remain first. Future Search never outranks a broken foundation.

Future-ready layer

Broader applicable Schema.org semantics, stable entity relations, evidence paths, optional machine indexes, browser-agent semantics and open change-notification mechanisms are tested as interoperability work.

Why go beyond today's Google gallery?

Google's structured-data documentation explicitly notes that Schema.org includes objects and properties Google does not currently require and that these may still be useful to other search engines, services, tools and platforms; some may support future Search features. ARWP therefore optimizes for a coherent public knowledge graph, not only today's SERP widgets.

The boundary stays strict: markup must describe real content. More properties are not automatically better.

Semantic index

ARWP can compile the canonical page manifest and entity catalog into one optional JSON-LD graph. Each page gets a stable page identity, isPartOf the canonical WebSite, and points to its reusable mainEntity. An ItemList exposes the canonical page inventory.

node bin/arwp-semantic-index.mjs build \
  registry/page-manifest.json \
  registry/entity-catalog.jsonld \
  --output=semantic-index.jsonld
node bin/arwp-semantic-index.mjs check semantic-index.jsonld

This is an optional interoperability surface, not a new standard discovery file and not a ranking declaration.

Evidence paths, not keyword pages

For technical, research and dataset content, ARWP prefers a traceable path such as intent → canonical answer → section → method/data/tool/example → citation or owner outcome. Relations such as citation, isBasedOn, hasPart, subjectOf, about and mainEntity are used only when true.

Bing grounding queries and Search Console query+page evidence feed this graph. A new query is not an instruction to generate another thin URL.

Browser-agent operability

Interactive sites should prefer native semantic HTML and accurate accessible names, roles and states. OpenAI documents that ChatGPT Agent in Atlas uses ARIA labels and roles to interpret interactive elements. ARWP combines bounded static review with required rendered/runtime verification.

Experiment maturity

  1. Foundation — useful when applicable on interoperability merits; not a ranking-factor label.
  2. Experiment — bounded implementation with explicit verification and rollback.
  3. Watch — research/prototype only; not a default requirement.
