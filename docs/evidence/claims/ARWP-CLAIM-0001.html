ARWP-CLAIM-0001

A2A 1.0 callable interfaces come from supportedInterfaces[], not from the URL used to fetch the Agent Card.

Status: verifiedReviewed 2026-09-05A2A 1.0 scope
For A2A 1.0, an Agent Card is discovery metadata. A client selects a supported AgentInterface and sends requests to the URL declared by that selected supportedInterfaces[] entry; the Agent Card discovery URL is not automatically the callable A2A endpoint.

Structured facts

A2A version1.0
Standard well-known discovery/.well-known/agent-card.json
Callable URL fieldsupportedInterfaces[].url
Client ruleSelect the first compatible interface in preference order and use its URL/protocol binding/version.

Scope

This is about discovery vs callable endpoint semantics. It does not assert that an advertised endpoint is reachable, that the caller is authorized, or that a signed card makes its provider trustworthy.

Why ARWP records this claim

An earlier ARWP implementation could treat the fetched card document as the callable agent endpoint. The project corrected that protocol-semantics defect and now preserves the card URL as provenance while routing to the declared interfaces. The claim exists so downstream users can cite the exact rule and evidence instead of reverse-engineering it from code.
