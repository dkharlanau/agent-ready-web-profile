Pattern A — visible in AI search, opt out of documented training crawlers

ARWP publishes a conservative starter robots block that keeps the currently documented search crawlers open while blocking the explicit OpenAI/Anthropic/Google training-side controls.

Open template

This does not make a site appear in any AI answer. It only avoids blocking the documented access paths that may contribute to search visibility while expressing available training opt-outs.

Pattern B — open search + training

For sites that intentionally permit both technical crawl access and reuse/training, a separate template allows those documented controls. Copyright permission should still be stated separately; ARWP uses media/rights.json for that purpose.

Important exceptions

  • Google-Extended is a robots product token, not a dedicated request User-Agent. Blocking it does not affect Google Search or Search AI features.
  • Perplexity-User is intentionally unresolved here: current official crawler docs say user-triggered fetch generally ignores robots.txt, while a newer help article says the old blocked-URL summary behavior was disabled. ARWP does not choose a side until the official documentation converges.
  • Bing documents robots meta/X-Robots-Tag directives that affect Chat/Copilot display and generative-AI training usage. There is no dedicated training-crawler row inferred from Bingbot.
  • WAF/CDN access can still block a legitimate crawler even when robots.txt allows it. Provider IP verification is a separate operational concern.

Policy boundary

robots.txt is an access/crawling control, not a copyright license. A site can technically allow GPTBot or ClaudeBot while withholding reuse rights, or explicitly license training reuse while a WAF blocks the crawler. ARWP tracks those as separate surfaces because collapsing them creates false certainty.
