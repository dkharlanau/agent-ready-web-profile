SITE FOCUS / V0.2

Own a problem.
Draw the boundary.

First declare what the site is meant to solve. Then observe what it actually exposes. Cite Goose compares the two without turning product strategy into another opaque SEO score.

DECLARE → OBSERVE → COMPARE

Give the engine a product boundary.

Version 0.2 adds .arwp/site-focus.json: an owner-declared thesis, IN / ADJACENT / OUT scope, problem lanes, primary navigation contract and route roles. Repository mode finds it automatically; live mode can receive it explicitly.

arwp-focus https://example.com --focus-profile=.arwp/site-focus.json arwp-focus https://example.com --focus-profile=.arwp/site-focus.json --json arwp-focus https://example.com/project/ --repo-root=. --output=site-focus-report.json

Declared truth

Primary problem, audience, useful outcome, proof, action, scope and intended navigation come from the owner contract.

Observed truth

Homepage wording, links, page jobs, proof/action signals and sampled graph structure still come from the actual site.

Drift

The report shows missing or unexpected navigation, unclassified routes and thesis wording drift without pretending those signals are ranking factors.

PAGE ROLES

Depth is allowed. Competing identities are the problem.

Problem / commercial

Pages that directly solve the primary problem or carry the product/commercial continuation.

Proof / trust

Projects, research, experiments, evidence, methodology and utility pages can support the thesis without sharing homepage vocabulary.

Technical reference

APIs, schemas, protocols and deep implementation material stay available without becoming another first-order product identity.

Route families are not problem territories. A focused multilingual product can have many content families; a studio can have hundreds of routes. The engine now asks what role those routes play.

LOCALE EQUIVALENCE

Translations are not duplicate-intent pages.

When locale prefixes are declared, structurally equivalent localized routes are removed from MERGE noise. This only fixes the product-focus diagnostic; canonical and hreflang correctness still belongs to technical Search validation.

EXECUTABLE DIAGNOSTIC

Inspect the structure before arguing about it.

The Site Focus Engine produces independent diagnostics instead of one opaque score: navigation breadth and drift, route-role coverage, audience signals, duplicate-intent pairs, orphan candidates, pages without proof/action signals and a Page Contract Map.

KEEP / NARROW

Keep a coherent page, or tighten a page whose job and next action are unclear.

MERGE / DEFER

Surface non-locale intent overlap or declared scope-placement conflicts for human review.

No auto-delete

REMOVE and SPLIT are never automatic. URL history, redirects, traffic and the real product boundary still require review.

No focus/readiness/ranking score. Similarity thresholds and navigation limits are Cite Goose review heuristics, not Search or AI platform requirements.

THE SITE THESIS

One sentence before one hundred pages.

For [primary audience] who need to [solve a concrete problem], this site provides [distinct useful mechanism / evidence / tool] so they can [useful outcome].

Boundary rule: a related idea is not automatically an in-scope page. It must strengthen the site's primary problem, useful outcome or proof.

SCOPE LEDGER

Use three buckets.

IN

Directly solves the primary problem, explains the mechanism, supplies evidence or enables the next useful action.

ADJACENT

Supports the core problem but stays subordinate. It can live below a hub without becoming another identity for the site.

OUT

Interesting and related, but not important enough to the core problem. Defer it, remove it or give a genuinely distinct problem territory its own resource.

CITE GOOSE HOUSE HEURISTIC

Small architecture first.

1primary problem territory
≤3homepage problem lanes
≤5primary navigation destinations
1dominant action per page

These are house heuristics, not ranking factors or platform requirements. Their purpose is to force a coherent first draft. Change them when the site's real audience and evidence justify another architecture.

PAGE CONTRACT

Every route needs a job.

page_job: what this page helps the visitor do primary_question: the question it answers in_scope: what belongs here out_of_scope: what belongs elsewhere proof: source, data, example, tool or first-hand evidence primary_action: next useful step parent_hub: one canonical owning section

If a proposed route cannot fill this contract without duplicating another page, it is a backlog idea rather than a new URL.

TRANSFORMATION HANDOFF

Focus can propose. It cannot mutate.

Accepted NARROW, MERGE and declared-scope review decisions can now be passed forward as proposal-only Target Transformation candidates. The handoff is explicitly non-executable until a human accepts the decision and exact repository targets, redirect/history implications and verification steps are resolved.

VISUAL + PERFORMANCE

Be memorable without becoming heavy.

Recognizable

Use a small tokenized palette, strong type hierarchy and a few large compositional moves instead of generic component-grid styling.

Useful

Visuals should explain hierarchy, evidence or mechanism. Do not hide essential text in imagery or let decoration weaken contrast and keyboard access.

Fast

Prefer static HTML/CSS, self-hosted fonts, compressed modern media with explicit dimensions and no third-party JavaScript required for core content.

Use field Core Web Vitals where available and lab tooling as diagnostics. Do not convert a lab score or an arbitrary kilobyte target into outcome evidence.

AGENT LOOP GATE

Run focus before expansion.

When a site is new, being redesigned or has become broad, start with the arwp-site-focus skill and executable Focus report. Declare the intended thesis and boundary, compare them with observed routes, then route accepted work into discoverability, content, technical eligibility, evidence, transformation or measurement specialists.
