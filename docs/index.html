The practical problem

A website can be rich in machine-readable resources and still look like “just HTML” to an external agent.

Without ARWP

  1. Search for the website
  2. Scrape HTML
  3. Guess undocumented URLs
  4. Maybe discover an API or dataset
  5. Maybe lose provenance and review state
Integration depends on guessing.
→

With ARWP

  1. Open one profile
  2. See the interfaces the site declares
  3. Choose the best available source
  4. Verify that source is live
  5. Keep canonical identity and provenance
Integration starts from evidence.

ARWP does not make an AI smarter. It removes guessing about how a website can be used.

What changes

One small file creates a stable machine entry point.

ARWP describes existing surfaces. It does not duplicate the site's domain knowledge.

01

For site owners

Stop documenting every machine interface differently for every AI client. Publish one discoverable map and validate it in CI.

02

For AI agents

Keep licensing, citation, provenance, review policy and security surfaces attached to the integration map.

Adopt ARWP

Start from a website you already have.

The scanner looks only for bounded, observable public evidence. It will not invent MCP, WebMCP, Agent Skills or A2A because a page mentions them.

1 · Scan — see what can be observed.

2 · Generate — create a conservative draft.

3 · Validate — keep the profile correct in CI.

4 · Connect — expose declared data through an agent integration when useful.

Install from the repository
git clone https://github.com/dkharlanau/agent-ready-web-profile.git
cd agent-ready-web-profile
npm ci
Observe the site
node bin/arwp.mjs scan https://example.com
Generate a validated draft
node bin/arwp.mjs init https://example.com

This GitHub Pages deployment cannot safely scan arbitrary websites by itself. The repository includes a bounded scanner service runtime; when a hosted endpoint is configured, this same UI switches to live scanning.

Use ARWP

Turn a static knowledge site into an agent-readable source.

The generic gateway is a consumer of ARWP, not the definition of ARWP. Domain-specific MCP servers remain preferable when semantics or safety need custom logic.

STDIO

Local MCP

Point the generic read-only gateway at any valid profile.

ARWP_PROFILE=https://example.com/ai/site-profile.json npm run mcp:start
HTTP

Remote MCP

Run the same bounded tools through stateless Streamable HTTP.

ARWP_PROFILE=https://example.com/ai/site-profile.json \
ARWP_HTTP_ALLOWED_HOSTS=mcp.example.com \
npm run mcp:http
FED

Federated router

Use the directory to select multiple ARWP sites, then search their declared retrieval surfaces without merging their canonical knowledge.

Technical layer

Existing mechanisms stay separate.

After the value is clear, the profile tells software which concrete standards and conventions the site actually supports.

WEB

Web discovery

Canonical HTML, sitemaps, robots policy, feeds and optional llms.txt.

DATA

Data & APIs

Machine-readable records, JSON Schema, OpenAPI, releases and dataset metadata.

RET

Retrieval

Search/RAG distributions with stable identity, citations and explicit no-match behavior where needed.

SKILL

Agent Skills

Real portable SKILL.md procedures. Instructions are not treated as a tool transport.

WEBMCP

WebMCP

Browser pages that actually expose structured tools at runtime.

MCP

MCP

Real local or remote servers. Static JSON does not become MCP by declaration.

A2A

A2A

Agent Card discovery only when a real remotely callable agent exists.

TRUST

Identity & trust

Stable IDs, licensing, provenance, review state, citation and security surfaces.

Boundaries

Useful because the claims stay narrow.

ARWP should get smaller when an upstream standard solves the same discovery problem better.

Not an SEO ranking mechanism. Search still depends on ordinary content, crawlability and indexing.

Not a permission layer. Metadata never grants access, authorization or execution rights.

Not another MCP. MCP is one capability ARWP can point to.

Not an AI-readiness score. The project reports evidence and verification states, not a vanity number.
