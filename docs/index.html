The practical problem

The web does not need another manifest that pretends every other discovery mechanism will disappear.

Without a resolver

  1. Search or scrape the site
  2. Guess which discovery file matters
  3. Read several incompatible metadata shapes
  4. Silently choose when declarations disagree
  5. Lose why an interface was trusted
Integration depends on site-specific logic.
→

With ARWP Resolver

  1. Observe bounded public discovery
  2. Normalize existing standards and conventions
  3. Keep source authority with every interface
  4. Surface conflicts instead of hiding them
  5. Plan the best interface for the intent
Integration starts from inspectable evidence.

ARWP does not make an AI smarter. It removes guessing about how a website can be used.

Resolve, do not replace

Existing standards keep their own semantics.

The resolver treats the ARWP profile as one useful publisher source — not as a mandatory universal manifest.

RFC

API & authorization

RFC 9727 API Catalog and RFC 9728 Protected Resource Metadata are resolved as IETF-standard evidence rather than copied into new ARWP semantics.

A2A

Agent discovery

A2A Agent Cards remain the protocol-native description of a callable agent and its supported interfaces.

SKILL

Portable procedures

Agent Skills discovery points to the real Skill artifacts; ARWP does not turn instructions into a transport.

MCP

Tools

MCP metadata is preserved separately from live runtime conformance. Experimental Server Cards remain labeled experimental.

Try the resolver

Start from a website, not from a schema.

The bounded resolver can discover useful surfaces even when the site has no ARWP profile. A publisher profile remains valuable when the site wants to explicitly declare retrieval, trust or integration surfaces that ordinary discovery cannot prove.

Resolve — normalize available discovery.

Explain — see evidence and conflicts in plain language.

Plan — select an interface for a concrete intent.

Profile — optionally publish a stable publisher-maintained ARWP map.

Website resolverCLI ready

Resolve all discovery
node bin/arwp.mjs resolve https://example.com
Explain what was found
node bin/arwp.mjs explain https://example.com
Plan for search
node bin/arwp.mjs plan https://example.com --intent=search
Observe / bootstrap ARWP profile
node bin/arwp.mjs scan https://example.com
node bin/arwp.mjs init https://example.com

GitHub Pages cannot safely resolve arbitrary external sites server-side. The repository includes one bounded hosted service with fixed /scan, /resolve, /explain and /plan routes. Until that HTTPS runtime is deployed, this UI prepares local commands.

Boundaries

Interoperability, not another readiness score.

Resolver output should remain inspectable.

Not an SEO ranking mechanism. Ordinary web fundamentals still matter.

Not a permission layer. Metadata never grants access or authorization.

Not another MCP/A2A/OAuth/API standard. Native protocol metadata remains authoritative for its own semantics.

Not a speculative catalog. New ARWP fields need concrete integration failures.
