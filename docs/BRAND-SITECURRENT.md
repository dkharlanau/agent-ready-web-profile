# SiteCurrent brand system

Reviewed: **2026-09-07**.

## Brand architecture

**SiteCurrent** is the product brand for the adaptive website-improvement experience built by the **Agent-Ready Web Profile (ARWP)** open-source project.

The repository, npm package, protocol/profile names and technical compatibility language remain **Agent-Ready Web Profile / ARWP**. SiteCurrent is the human-facing product identity. This avoids breaking the existing technical ecosystem while giving the product a name that is easier to remember and explain.

Use:

> **SiteCurrent**  
> Adaptive website improvement, powered by ARWP.

## Core idea

The web does not stand still. Search changes. AI discovery changes. Crawlers change. Agent interfaces change. Platform guidance changes. A website that was well prepared six months ago can quietly drift behind.

SiteCurrent exists to keep the website itself moving with that environment.

It does not stop at a score or a generic list of SEO tasks. It asks:

1. What changed upstream?
2. What actually applies to this site?
3. What is missing or stale here?
4. What should change, exactly where?
5. Can the change be made safely?
6. How do we verify it?
7. What happened afterward?

## Primary promise

> **Keep your site ready for what finds it next.**

This line deliberately works across classic Search, generative search, AI citations, recommendation surfaces and browser agents without pretending any one platform controls the future of discovery.

## Brand rhythm

The short benefit rhythm is:

> **Found. Understood. Cited. Used.**

It describes the four outcomes the system is designed to support:

- **Found** — technically eligible and discoverable where the publisher intends.
- **Understood** — clear content, identity, entities, structure and provenance.
- **Cited** — evidence and useful source material are addressable and attributable.
- **Used** — people and compatible agents can reach useful content or actions.

These are product goals, not guaranteed outcomes.

## One-line description

**SiteCurrent watches how Search, AI and web agents change, checks what actually applies to your website, and turns that into specific, verifiable improvements — down to repository changes when it is safe.**

## Short pitch

Most website-audit tools tell you what is wrong today. SiteCurrent is designed for the harder problem: keeping a real site aligned with a web that keeps changing.

It maintains dated best-practice intelligence, audits the target site, filters out irrelevant tactics, compiles the useful ones into an upgrade graph, resolves safe changes to exact files, verifies the result and keeps implementation evidence separate from ranking or citation claims.

The result is less chasing platform updates, less generic SEO/GEO cargo cult, less developer guesswork and a much shorter path from **new signal** to **verified site improvement**.

**CTA:** `See what your site needs now`

### More technical

From upstream platform changes to a target-repository pull request, SiteCurrent keeps the recommendation, implementation and evidence chain connected.

**CTA:** `Run the upgrade graph`

### More product-led

SiteCurrent continuously turns the latest useful Search, AI and agent practices into site-specific work — without fake scores, invented facts or blindly copied tactics.

## Benefits

### Stay current without chasing every update

The intelligence is versioned and dated. Guidance that needs review becomes `review-due` instead of surviving forever as a stale checklist item.

### Change the right things

SiteCurrent detects the site type and evidence gaps before recommending a mechanism. A dataset workflow should appear for a real reusable corpus, not for every marketing site.

### Move from advice to implementation

Applicable recommendations become exact target surfaces, recipes, dependencies and verification contracts. Deterministic, grounded changes can be promoted into digest-gated repository operations and reviewable pull requests.

### Keep truth and policy gated

Editorial judgment, publisher policy, authenticated owner settings and runtime/security decisions do not become automatic merely because an agent can edit files.

### Learn from the result

A successful build proves implementation, not ranking. SiteCurrent keeps outcome measurement separate and preserves neutral or negative results so the next cycle can be smarter.

## Category language

Preferred category:

> **Adaptive website improvement system**

Secondary descriptors:

- evidence-to-change engine;
- continuous web readiness system;
- Search / AI / agent website operations;
- target-site upgrade intelligence.

Avoid making **SEO tool**, **GEO score**, **AI visibility checker** or **autonomous content generator** the primary category. Those descriptions are too narrow and erase the implementation/evidence loop that differentiates the product.

## Voice

SiteCurrent should sound curious, sharp and technically literate without sounding like a vendor press release.

Prefer:

- “Here is what changed.”
- “This applies to your site because…”
- “Here is the exact surface to change.”
- “This is still owner-controlled.”
- “The implementation passed; the outcome is not known yet.”

Avoid:

- “Dominate AI search.”
- “Guaranteed rankings.”
- “Future-proof forever.”
- “One weird GEO trick.”
- generic AI language such as “revolutionary”, “game-changing” or “unlock the power of”.

## Visual identity

The visual idea is **current + direction + a stable site node**: the web keeps moving around a site, while the system continually brings the site back into a verified current state.

### Palette

- **Current Ink** — `#0B1020` — primary dark/background/text.
- **Current Mint** — `#63E6BE` — active signal/change/accent.
- **Current Ice** — `#E9FFF8` — light accent surface.
- **Current White** — `#FFFFFF` — neutral surface.
- **Current Slate** — `#687083` — secondary text.

The palette is intentionally not the usual blue-purple “AI gradient”.

### Mark

The mark uses two flowing strokes around a central site node. The open circular motion suggests continuous adaptation rather than a finished one-time audit. The small square represents the target website/repository. An arrow tip gives the mark direction without turning it into a generic growth chart.

## Relationship to ARWP

Use the relationship consistently:

- **SiteCurrent** — product brand and user-facing promise.
- **Agent-Ready Web Profile (ARWP)** — open-source project, technical foundation and compatibility/profile terminology.
- `agent-ready-web-profile` — repository and npm package identity.

Do not rewrite historical technical records solely to replace ARWP with SiteCurrent. Product-facing surfaces should lead with SiteCurrent; protocol/specification and attribution surfaces should preserve ARWP.
