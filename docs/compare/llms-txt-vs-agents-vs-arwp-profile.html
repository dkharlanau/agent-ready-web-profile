llms.txt vs agents.* vs ARWP profile

Reviewed 2026-09-07CC BY 4.0
Short answer: these surfaces solve different problems. llms.txt is a text-oriented convention for helping language-model consumers navigate useful site content. agents.txt/agents.json are community conventions that ARWP can read as agent-facing declarations. The ARWP profile is optional project-native structured publisher metadata. A resolver should use them as evidence, not require any one of them.

Why not choose one universal file?

The web already has different layers: ordinary HTML, sitemaps, API descriptions, A2A Agent Cards, MCP metadata, Agent Skills and browser-runtime capabilities. A single publisher file cannot honestly replace all of them. Extra metadata is useful only when it adds information that upstream or directly observed evidence does not already provide.

How ARWP uses them

The Resolver can discover all three surfaces and normalize them into one evidence-backed service map. The ARWP profile remains optional by design: a site with no ARWP file can still be resolved from ordinary web and upstream-native signals.

Practical publishing rule

Publish llms.txt when curated readable navigation is genuinely useful. Publish agents.* only when the declarations reflect real capabilities. Publish an ARWP profile when richer structured site metadata is useful to ARWP-aware tooling. Do not create duplicate files merely to look “AI-ready.”

Boundary

ARWP treats community and project-native declarations as evidence classes. They are not permission, security certificates or automatic search-ranking signals.
