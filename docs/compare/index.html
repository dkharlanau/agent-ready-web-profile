ARWP vs alternatives.

Short answer: ARWP is best classified as an agentic web interoperability resolver: it discovers heterogeneous website interfaces, preserves where each observation came from, keeps conflicts visible, and selects an interface for a concrete intent. Agent-readiness standards and scanners are the closest adjacent category. AI visibility platforms, crawler controls and individual protocols solve different parts of the stack.

Preferred product class

Agentic web interoperability resolver

This class name is project-defined, not presented as an industry standard. It is intentionally narrower than “agent readiness platform” and broader than any one protocol such as MCP, A2A, WebMCP or llms.txt.

Closest adjacent product

ARWP vs AgentReady / Ora

AgentReady is an open specification for what products should implement to be usable by agents. Ora is a reference implementation with 100+ checks, scored scans, real-agent journeys, discovery and a directory. That makes it the closest current comparison.

Interpretation: there is meaningful overlap, but the products optimize different decisions. AgentReady/Ora asks “how ready is this product for agents?” ARWP asks “what agent-facing interfaces actually exist, which one should be used for this intent, and why?”

Do not confuse product and protocol

MCP, A2A, WebMCP and llms.txt are not ARWP competitors.

They are upstream mechanisms that can become resolver evidence. MCP is a tool/context protocol; A2A describes agent-to-agent discovery and interaction; WebMCP exposes structured browser-page tools; llms.txt is a text-oriented content-routing convention. OpenAPI, RFC 9727, RFC 9728 and Agent Skills likewise keep their own semantics. ARWP's job is to discover and reconcile these surfaces, not replace them.
