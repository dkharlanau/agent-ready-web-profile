WebMCP vs MCP

Reviewed 2026-09-07CC BY 4.0
Short answer: MCP and WebMCP expose tool-like capabilities at different boundaries. MCP is a client-server protocol for capabilities provided by an MCP server. WebMCP lets a web page expose browser-context functions or forms as tools to an agent operating in that page. They are complementary, not interchangeable.

When MCP is the natural fit

Use MCP when the capability belongs in a server boundary: a reusable service, data/tool provider, local process or remote integration that should not depend on one rendered page. MCP's current 2026-07-28 generation keeps the protocol core stateless and makes discovery an explicit optional capability.

When WebMCP is the natural fit

Use WebMCP when the useful action already lives in a web application and the browser context matters. The WebMCP draft describes client-side tools exposed by a page to AI agents. That can avoid rebuilding the same interaction as a separate backend integration, but it also means browser/runtime evidence matters.

Why a resolver should keep both

A site can legitimately expose both. A backend MCP server may provide broad programmatic capabilities while WebMCP exposes page-local actions. ARWP therefore records protocol, scope and evidence separately instead of ranking one technology as universally better.

Boundary

Tool discovery is not authorization to execute a tool. Runtime availability is not evidence that an action is safe or intended for the current user.
