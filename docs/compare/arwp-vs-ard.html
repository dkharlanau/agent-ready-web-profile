ARWP vs Agentic Resource Discovery (ARD)

ARD and ARWP overlap around discovery, but they operate at different layers. ARD v0.91 is an upstream federated resource-description/discovery/search proposal. ARWP is site-first interoperability tooling that resolves the interfaces a website actually exposes across ordinary web, API, agent and trust surfaces.

ARD v0.91 proposal · 26 Aug 2026ARWP 0.2 toolchainCC BY 4.0 comparison
Short answer: ARWP should consume ARD, not compete with it. ARD helps agents publish/find candidate MCP servers, A2A agents, Skills, APIs and registries through a common discovery layer. ARWP starts from a website, combines ARD with ordinary web discovery and other protocols, preserves source authority and conflicts, and chooses an interface for a concrete intent.

What changed in ARD v0.91

  • The canonical static path is now /.well-known/ard.json.
  • The current link relation is rel="ard".
  • The description layer is expressed with JSON-LD, a base context and namespaces.
  • In-page JSON-LD can advertise ARD resources.
  • The predecessor /.well-known/ai-catalog.json / rel="ai-catalog" path can remain a compatibility signal.
  • Registry search/federation remains a different execution path from merely discovering a site manifest.

What ARWP currently implements

  • canonical /.well-known/ard.json probe;
  • HTTP Link: ...; rel="ard" discovery;
  • predecessor ai-catalog fallback if canonical ARD is absent;
  • conservative typed evidence for MCP Server Cards, A2A references, Skills, registries, nested catalogs and other artifacts;
  • no automatic ARD registry federation/search;
  • no claim yet of full v0.91 JSON-LD namespace/in-page conformance.

What ARWP still adds

Ordinary HTML and HTTP discovery when ARD does not exist; multiple competing publisher/upstream sources on one site; source authority and visible contradictions; intent planning across read/search/structured/tools/agent paths; and runtime verification kept separate from static metadata.

Product decision

ARWP should not add profile fields that duplicate ARD. The next interoperability work should complete v0.91 JSON-LD namespace and in-page discovery, then evaluate bounded explicit registry search without recursively chasing the ecosystem or changing planner decisions without benchmark evidence.
