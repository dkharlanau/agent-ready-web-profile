ARWP vs Agentic Resource Discovery (ARD)

ARD and ARWP overlap around discovery, but they operate at different layers. ARD is an upstream federated catalog/search specification for agentic resources. ARWP is site-first interoperability tooling that resolves the interfaces a website actually exposes across web, API, agent and trust surfaces.

ARD v0.9 draftARWP 0.2 toolchainCC BY 4.0 comparison
Short answer: ARWP should consume ARD, not compete with it. ARD helps an agent find candidate MCP servers, A2A agents, Skills, APIs and registries across federated catalogs. ARWP starts from a website, combines ARD with ordinary web discovery and other protocols, preserves source authority and conflicts, and chooses an interface for a concrete intent.

Why ARD matters to ARWP

  • ARD v0.9 defines /.well-known/ai-catalog.json as the publisher capability manifest.
  • It supports discovery through the well-known URI, rel="ai-catalog", a robots Agentmap directive and DNS/SVCB pointers.
  • It defines a REST registry search layer and explicitly keeps relevance scores separate from trust evaluation.
  • Its media-type envelope can reference A2A Agent Cards, MCP Server Cards, Skills, nested catalogs and registries.
  • ARWP already had partial ai-catalog parsing; after this review that support is classified as ARD-related rather than MCP-native discovery.

What ARWP still adds

  • ordinary HTML and HTTP discovery when no agentic catalog exists;
  • multiple competing publisher/upstream sources at the same site;
  • source authority and visible contradictions;
  • intent planning across read, search, structured, tools and agent paths;
  • runtime verification kept separate from static metadata;
  • dated Search/Agent recommendation audits and visibility evidence.

Product decision

ARWP should not add new profile fields that duplicate ARD. The better path is an ARD adapter with full media-type coverage, trust/provenance preservation and optional registry search. When ARD can express a capability cleanly, ARWP should point to or resolve the upstream artifact rather than create parallel syntax.
