ARWP vs AgentReady / Ora

AgentReady/Ora and ARWP both address the emerging problem of websites and products being usable by AI agents. They differ in the product question they optimize for.

AgentReady v1.0 · Aug 2026ARWP 0.2 toolchainCC BY 4.0 comparison
Short answer: AgentReady defines what a product should implement to be usable by agents, and Ora operationalizes that idea with many checks, scores, grades and real-agent journeys. ARWP asks a different question: what interfaces does this website actually expose, which one should an agent use for this intent, what source supports that decision, and where do discovery sources disagree?

Where AgentReady is stronger today

  • a clear, compact readiness vocabulary built around find/read/act;
  • large-scale scanner/ranking operation rather than a small reference cohort;
  • 100+ checks in the full Ora ranker;
  • real-agent journey evaluation as a first-class product;
  • a public readiness dataset/research program that revises recommendations from observed agent behavior.

Where ARWP is intentionally different

  • no requirement that one manifest or readiness score become universal;
  • site-first resolution even when the publisher has no ARWP profile;
  • source authority, provenance and contradictions attached to the selected interface;
  • explicit distinction between static declarations and runtime verification;
  • upstream protocols remain authoritative rather than being copied into new ARWP semantics.

What ARWP should learn from AgentReady

The strongest idea to borrow is not the score. It is the empirical loop: trace actual agent behavior, publish the dataset/methodology, update recommendations from evidence and show real task outcomes. ARWP's differentiator becomes stronger if its resolver benchmark, browser-agent evaluations and external-site corpus grow alongside its protocol model.
