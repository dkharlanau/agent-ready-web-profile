Entity graph · implementation proposals

Turn entity gaps into grounded repository proposals.

ARWP can now connect an observed structured-data gap to first-party repository evidence without pretending that a machine should invent the missing fact. The output is a review-required remediation manifest, never an automatic mutation.

Read-only repo scanGrounded values onlyNo automatic writes

What changes when repository evidence is available?

A gap such as Dataset.license remains manual when ARWP cannot find a license. If the same Dataset already has a license in another first-party JSON-LD source, the engine may emit a JSON Patch proposal pointing to the exact evidence file, target file, JSON pointer and existing value.

Remediation lanes

  • Grounded JSON patch proposal — a value already exists in first-party structured evidence.
  • Grounded structured-data proposal — evidence exists but the target is embedded HTML JSON-LD.
  • Verify deployment — the repository already appears fixed; check build/deployment drift.
  • Content / entity-page / relationship / identity review — human judgment remains necessary.
  • Missing evidence review — ARWP refuses to guess.

Run the loop

node bin/arwp-entities.mjs https://example.com --output=entity-gap-report.json
node bin/arwp-entity-remediation.mjs entity-gap-report.json --repo-root=../site --output=entity-remediation.json

The repository scan is bounded and skips dependencies, generated build directories and symlinks.

Safety boundary

Generated operations are evidence-carrying proposals only. The engine never writes files, applies JSON Patch, deploys code, or invents authors, licenses, people, prices, ratings, reviews, events, credentials or relationships. HTML and Markdown remain review-only.
