Maturity needs evidence.

A recognizable owner, usable data, clear reuse terms and a history of verifiable changes are more useful than a collection of badges. ARWP remains pre-stable. This inventory makes its declarations inspectable without pretending they are independent certification.

What can be inspected now

Canonical entities connect Dzmitryi Kharlanau, the software, the website and research assets. The data catalog points to two real datasets, not newly invented research. Brand rules separate the project name from software licensing and registration. The measurement plan defines discovery, resource intent and independent adoption without inventing baseline numbers.

Security reporting, corrections, product history and configured build-provenance work remain in the Trust Center. The machine-readable evidence inventory links to their actual files.

What the checker verifies

Unique entity identifiers; named ownership; graph-to-dataset-page identity, licensing and download declarations; nonempty local artifacts; explicit DOI states; and measurement definitions that distinguish unknown from zero.

node bin/arwp-maturity.mjs check docs/maturity/profile.json
node bin/arwp-maturity.mjs receipt docs/maturity/profile.json

The receipt hashes the observed files and profile. It is unsigned, local and not proof of historical publication, legal clearance, security or search performance.

What still needs external evidence

No issued DOI or trademark clearance is claimed. Existing analytics source is not a verified provider account or consent test. Proposed custom events are not yet instrumented. Attestations must be checked against a real released artifact. Independent usage and search impact need observations, not metadata.

A valid inventory does not establish that the project is mature. It establishes that the selected static declarations are consistent.

Apply the pattern without adding clutter

Start with the site's actual owner and useful pages. Reuse existing canonical identifiers. Add a dataset page only when there is a genuine downloadable dataset with rights, method and limitations. Use an empty dataset list for sites without data. Publish a privacy and measurement statement that matches the deployed system, rather than copying promises from a template.

The next evidence worth producing

Prioritize a reproducible dataset release with a data dictionary and checksums; a case study with a denominator, dates and negative results; an independently maintained implementation; and a release compatibility/support policy the maintainer can actually honor. These are separate work items, not completed achievements.

For suitable ML data, consider Croissant after validating real record extraction. For archival citation, publish an actual versioned archive record before adding its DOI. Do not mint datasets, organizations, awards or review counts merely to fill a schema.

Search boundary

Google documents normal SEO foundations for its AI features, not a requirement for an ARWP maturity file. Dataset markup supports a specific data-discovery use case; brand policies and measurement plans serve clarity and accountability. Their existence does not demonstrate ranking or recommendation gains.
