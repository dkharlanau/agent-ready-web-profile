Discovery conflict

Status: project-definedReviewed 2026-09-05CC BY 4.0
A disagreement between independently observed or publisher-declared discovery sources that a resolver preserves rather than silently overwriting.

Examples

  • a publisher profile names one canonical identity while an upstream protocol card identifies a different service;
  • two metadata sources advertise different MCP endpoints for what appears to be the same capability;
  • a static declaration says an interface exists but live verification observes a different protocol/version/endpoint;
  • root-wide metadata advertises a broad capability that does not clearly apply to a path-scoped target.

Why keep conflicts visible

Silently picking one source hides uncertainty and makes resolver behavior harder to audit. ARWP keeps the competing observations, their source authority and the selection reason available to callers.

Not every difference is a conflict

Two complementary surfaces can coexist without contradiction. A site may expose HTML for reading, MCP for tools and A2A for agent interaction. Conflict is about incompatible claims or identity/routing evidence, not simple multiplicity.
