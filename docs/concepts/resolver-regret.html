Resolver regret

Status: project-definedReviewed 2026-09-05CC BY 4.0
A decision-quality case where a simpler discovery strategy selects the reviewed-correct interface while the union Resolver selects an incorrect one.

Why the metric matters

More discovery is not automatically better. A resolver that unions many signals can over-select broad, temporary or out-of-scope interfaces. Resolver regret makes that failure visible instead of allowing a large discovery count to hide worse decisions.

How ARWP uses it

For each reviewed benchmark case, ARWP compares the Resolver's selected interface with simpler strategies over the same reviewed truth. A regret case is counted when a simpler strategy is correct and the Resolver is not.

ARWP keeps reviewed ground truth frozen during a comparison. If live publisher capabilities appear to have changed, that is queued for explicit re-review rather than silently rewriting truth to improve the score.

What it is not

Resolver regret is not user regret, model answer quality, latency, token cost or a universal benchmark metric. It is an ARWP decision-quality diagnostic.
