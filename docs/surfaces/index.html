Search Surface Blueprint

A conditional architecture for deciding which pages and technical signals a site should actually maintain. It separates current Search guidance from useful product/editorial surfaces and refuses to turn every possible page type into a universal SEO requirement.

Site archetypes

Software product

Core: home, product, docs.

Usually useful: changelog, updates, profile, evidence. Roadmap is optional.

Service business

Core: home, services.

Usually useful: about, profile, case studies, updates.

Editorial / news

Core: home, updates, author profiles.

Usually useful: topic hubs, trust/corrections and media. News-specific mechanisms stay news-only.

Documentation / research

Core: home, docs.

Usually useful: research, datasets, profiles, updates and evidence.

E-commerce

Core: home and specific product leaf pages.

Product/merchant markup is not applied to generic category pages.

Portfolio

Core: home and profile.

Products, research, updates and case evidence are conditional.

Local business

Core: home and services.

About, trust, updates and real-world business facts matter more than decorative schema.

New technical checks

  • Host identity: WebSite/site-name and favicon boundaries at domain/subdomain scope.
  • Search presentation: distinct titles, page-specific descriptions and intentional snippet controls.
  • Crawl architecture: self canonicals, sitemap alignment, crawlable internal links, descriptive anchors, real URLs instead of fragment-only state.
  • 2 MB boundary: flag HTML approaching the current Googlebot fetch limit so critical title/canonical/content/structured data stay early.
  • Visual discovery: preferred page image, large-image preview eligibility and original/non-clickbait Discover content.
  • Freshness: truthful lastmod, visible publication dates and conditional news sitemaps.
  • Product history: softwareVersion/releaseNotes plus real changelog/release leaves.
  • AI citation: clear sections/tables when useful, evidence and cited sources, cross-format entity consistency.

Anti-cargo-cult rules

  • Roadmap and changelog are useful product surfaces, not Google rich-result types.
  • NewsArticle and news sitemap are for genuine news publishing, not ordinary product releases.
  • FAQ sections are for recurring user questions; FAQ markup is not a generic rich-result tactic.
  • Service/OfferCatalog semantics do not imply a Google rich-result feature.
  • Software structured data never justifies inventing rating/review data to satisfy rich-result eligibility.
  • Comparison pages must provide real decision value rather than scaled keyword matrices.

Run it

node bin/arwp-surfaces.mjs https://example.com --kind=software-product --json
node bin/arwp-improve.mjs https://example.com --site-kind=software-product

The first command exposes the full conditional surface report. The second merges it into Growth, Entity Graph and page-link evidence and selects a smaller implementation backlog.
