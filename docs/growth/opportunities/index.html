ARWP · Search opportunity planning

Which search landing page should you improve next?

Start with a real user need, an existing page and something useful that only your project can provide. Add Search Console evidence when you have it. Do not turn missing data into a keyword-volume estimate.

This tool produces a review queue. It matches an editor-reviewed query map to a joint query-and-page export, separates declared brand terms and identifies pages to inspect. It does not forecast rankings, create articles or merge pages.

Run an example without an account or API key

Use Node.js 20 or later from the repository checkout. The example maps four ARWP user needs to actual project destinations. Its query phrases are hypotheses, not verified search volumes.

git clone https://github.com/dkharlanau/agent-ready-web-profile.git
cd agent-ready-web-profile
node bin/arwp-opportunities.mjs templates/growth/arwp-opportunity-map.json
node --test scripts/search-opportunities-test.mjs

The planner itself needs no dependency installation and makes no network requests. Without owner data it reports no-owner-data, leaves observations unknown and proposes baseline/evidence checks.

Use a joint query-and-page export, not two unrelated tables

Google's Search Analytics API can group rows by both query and page. Use final web data, one period and one country/device segment. Do not join the independent totals from the Queries and Pages CSV tabs: that would invent which query belongs to which page.

node bin/arwp-opportunities.mjs my-map.json \
  --search-console=private/query-page.json \
  --output=private/review.json --json

The directory must exist and the output file must be new. Keep owner exports and reports private. The tool accepts a documented JSON wrapper around the query-page response, not an arbitrary Search Console CSV.

What the evidence can—and cannot—tell you

An existing page has non-brand impressions. Review whether it answers the task, offers an original worked example and makes the next action possible. The default position band above 3 through 20 is a scheduling heuristic, not a Google rule or an expected win.

Several pages appear for the same query. Inspect intent, device/country and canonical URLs. They may serve different needs. The tool emits a review task, never an automatic merge, redirect or noindex instruction.

A query has no matching rows. The export may omit data, or the site may have little visibility. That is not proof of zero demand. Keep the query as a research hypothesis.

A page has many clicks. Clicks do not establish product use. Specify and verify a useful next action: complete a diagnostic, run a tool, try a worked example or finish a product task.

Google explains impressions, CTR, average position and page-versus-property aggregation.

A concrete example: improve the answer, not the page count

For a static-site audit, the useful contribution is a runnable diagnostic with an explanation of failed checks. For a protocol comparison, it is a reproducible interface-selection example. For a voice-practice product, a possible contribution is a working practice exercise—but only when that exercise exists and its claims have been checked.

One complete answer can serve related query variants. There is no need to generate a near-duplicate page for every phrase. Google recommends original, useful content and explicitly warns against scaled query-variant pages created to manipulate visibility.

Close the loop with outcomes

Choose one existing page. Record the proposed change and its commit. Verify the built page, evidence and next action. Compare complete before/after windows with matching filters, while recording seasonality and other changes. Keep neutral and negative results.

The planner's ranking and conversion impact fields are deliberately unknown. The existing ARWP visibility and experiment tools hold the separate outcome evidence; a passing test is not evidence of traffic growth.
