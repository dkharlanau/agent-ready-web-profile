ARWP Growth Loop

Audit your site. Improve the answer. Measure the result.

ARWP turns current Search, AI-search, recommendation, citation and agent-web evidence into explicit hypotheses and a prioritized site backlog. The loop is designed to keep learning instead of accumulating SEO/GEO folklore.

Loop: research → classify → technical preflight → baseline → hypothesis → implement → verify → measure → keep / revise / revert.

Which existing page should improve next?

A technical audit is the starting point. Map real user needs to existing landing pages, identify an original useful asset and define the next action a visitor can complete. Add a joint Search Console query-and-page export to prioritize observed opportunities without inventing search volume.

node bin/arwp-opportunities.mjs templates/growth/arwp-opportunity-map.json

The offline planner separates declared brand terms, highlights query-page overlap for human review and leaves missing evidence unknown. It does not generate thin pages, forecast rankings or automatically merge URLs.

Four evidence layers

Trend RadarTracks recent primary-source changes, maturity and owner-only controls; separates WATCH from ADOPT/MEASURED.
RecommendationsRecords dated requirements, guidance, features and measurement surfaces.
Growth hypothesesStates why a change may matter, applicable surfaces, checks and observable success signals.
Growth ProfileAudits a real site and turns applicable evidence into P0–P3 implementation actions.

Connect a site. Get a defensible improvement backlog.

node bin/arwp-trends.mjs list --since=90 --exclude-retired
node bin/arwp-hypotheses.mjs list --vertical=editorial
node bin/arwp.mjs technical-integrity https://example.com/ --max-pages=20 --json
node bin/arwp-growth.mjs https://example.com --vertical=editorial --json

The Growth JSON includes the actionable backlog plus the applicable hypothesis program. A hypothesis explains the reason and measurement model; it is not proof the platform will reward the change.

Where a platform setting can only be checked by the site owner—for example Google's current generative Search control—Growth emits an owner-side verification action instead of pretending public crawling can observe it.

Decision order

  1. Fix crawl/index/snippet eligibility blockers.
  2. Make canonical/freshness signals accurate.
  3. Improve original evidence and content usefulness.
  4. Make identity, authorship and sections resolvable.
  5. Add recommendation/citation opportunities that fit the site.
  6. Add agent-facing surfaces only for real agent use cases.
  7. Close the loop with owner-side outcome evidence.

Evidence classes

  • platform-requirement — eligibility/policy foundation.
  • platform-guidance — documented best-practice direction.
  • platform-feature — optional acquisition/distribution mechanism.
  • platform-measurement — owner-side feedback source.
  • project-experiment — research idea kept out of the default plan.

npx skills add dkharlanau/agent-ready-web-profile

Reusable artifacts

  • growth/hypotheses.json — machine-readable hypotheses.
  • templates/growth/growth-loop-checklist.md — site review contract.
  • templates/growth/hypothesis-ledger.md — before/after evidence.
  • skills/arwp-growth-loop/SKILL.md — executable agent methodology.

Resolver stays underneath

ARWP still resolves HTML/HTTP discovery, optional publisher profiles, APIs, ARD, Agent Skills, MCP, A2A and other supported evidence with provenance/conflicts intact. Growth work uses that interoperability foundation; it does not replace it.

ARWP cannot guarantee crawling, indexing, ranking, Discover placement, AI citations, recommendation traffic or conversion. Success must be measured on the publisher's real surfaces.
