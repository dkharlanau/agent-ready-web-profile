What the latest search changed

  • ARD v0.91 supersedes the v0.9 naming: current static discovery uses /.well-known/ard.json and rel="ard".
  • JSON-LD is now central to the ARD description layer: v0.91 introduces a base context and namespaces while keeping compatibility with earlier manifests.
  • Legacy ai-catalog remains compatibility evidence: ARWP keeps the predecessor /.well-known/ai-catalog.json/rel="ai-catalog" fallback, but no longer presents it as the canonical current ARD surface.
  • DNS-AID adds an independent domain/DNS route for agent discovery, while Web Bot Auth addresses cryptographic request identity.
  • AIPREF carries Content-Usage preferences through HTTP/robots work in progress; NLWeb and auth.md remain separate early mechanisms rather than mandatory readiness rules.

ARD vs ARWP: the important boundary

ARD is a federated resource-discovery/search specification: publish agentic resources, index them and search registries. ARWP Resolver is site-first interoperability tooling: inspect a website's heterogeneous web and agent surfaces, preserve source authority and conflicts, and choose an interface for a concrete intent. ARWP should consume ARD as upstream evidence rather than compete by inventing another catalog format.

Current ARWP support is deliberately partial: canonical ard.json, HTTP rel="ard", predecessor ai-catalog fallback and conservative typed entry normalization are supported. Full in-page JSON-LD namespace interpretation and bounded registry federation remain separate evidence-gated work.

Methodology boundary

This observatory records protocol/project facts and ARWP's implementation state. It does not measure web adoption, market share or protocol quality. Internet-Drafts are not RFCs. Community projects are not silently promoted to industry standards. A mechanism moves to supported only when corresponding resolver/runtime behavior exists and is tested.
