Trust should be inspectable.

ARWP does not use a single trust or readiness score. This page exposes who maintains the project, what evidence it uses, how corrections are handled, how releases can be verified, what remains external or planned, and what none of those signals prove.

Evidence model

  • primary sources are preferred for protocol/vendor facts;
  • owner-controlled examples stay separate from independent evidence;
  • negative results and resolver regret remain visible;
  • planned capabilities are not presented as deployed;
  • dated snapshots are frozen instead of rewritten.

Security

The resolver accepts public URLs and parses untrusted web metadata, so network boundaries and read-only behavior are security-relevant. Reports should follow the repository security policy rather than public exploit disclosure.

Security policySecurity page

Corrections

Material published factual errors are recorded in a public ledger. Benchmark improvements are preserved as revisions rather than relabeled as corrections, and superseded claims remain discoverable.

Corrections ledgerCorrections JSON

Build provenance

The npm ecosystem workflow uses GitHub OIDC/trusted publishing. The next npm publish is configured to attest the exact packed tarball with GitHub Artifact Attestations so consumers can verify repository/workflow/commit provenance.

gh attestation verify <tarball> -R dkharlanau/agent-ready-web-profile

Boundary: provenance proves where and how an artifact was built; it does not prove that the artifact is vulnerability-free.

Persistent citation

The repository is prepared for Zenodo archiving through CITATION.cff. No DOI is claimed yet. A DOI will be published here only after the repository is externally enabled/archived and Zenodo actually issues one.

Independent security signal

An OpenSSF Scorecard workflow is configured as an external, reproducible signal over repository practices. Its result is not treated as a correctness or quality certificate.

Reuse rights

Software remains Apache-2.0. Designated ARWP-authored press/research/media material is available under CC BY 4.0, including explicit AI/ML reuse permission where covered by the rights manifest.

What this Trust Center does not prove

It does not prove that ARWP is vulnerability-free, universally adopted, endorsed by upstream protocol owners, guaranteed to rank in search/AI systems, or correct outside each claim's stated evidence and date. Trust signals are useful because they are inspectable and bounded, not because they remove judgment.
