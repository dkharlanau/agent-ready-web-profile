PRIVACY / ANALYTICS / PUBLIC DATA

Measure less. Explain more.

The current Goose ARWP public site contains optional analytics code behind an explicit consent choice. This page documents the intended behavior and the limits of what the repository can verify.

Current intent

Analytics: opt-in

Public reporting: aggregate only

Unknown ≠ zero

Optional analytics

Where the Goose analytics consent component is present, the implementation is designed not to load Google Analytics until a visitor chooses “Allow.” The choice is remembered locally in the browser so the prompt does not need to reappear on every visit.

Repository evidence is not provider-account evidence. The source can show the consent gate and intended payload behavior. It cannot by itself prove provider-side retention settings, account configuration, geographic processing, deletion state or every browser/runtime outcome.

What the project tries not to collect or publish

  • No visitor-level analytics export should be published by the project.
  • Measurement plans require aggregate public reporting.
  • Unknown baselines remain unknown rather than being converted to zero.
  • Raw search queries, free-text submissions and submitted audit URLs should not be exposed in public evidence artifacts.
  • Owner-side provider exports should be minimized to the fields required for a defined experiment or decision.

Local browser state

The analytics preference is stored in browser local storage by the public-site consent component. Clearing browser storage can remove that local preference. The project should not treat a local consent flag as proof of provider-side deletion or as consent for unrelated processing.

External services and links

GitHub, Google Analytics and external sites linked from Goose operate under their own terms and privacy practices. Following an external link leaves the Goose project site. A partnership link does not make the external service part of the Goose privacy boundary.

When this page must change

Update the privacy surface when the project adds a form, account, hosted scan service, payment flow, new analytics provider, different consent mechanism, material new cookies/storage, personal-data collection or a new legally relevant processing purpose. Do not keep a generic policy while the actual product changes underneath it.

What this page does not claim

This is a factual project-data-use summary, not a jurisdiction-specific legal compliance statement. It does not claim GDPR, ePrivacy, CCPA or another regime is satisfied merely because a consent banner or privacy page exists.
