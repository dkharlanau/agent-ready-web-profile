ARWP ruleset 2026.09 · reviewed 5 September 2026

Search + Agent Recommendations

A living, source-backed implementation layer for sites that want to stay discoverable in classic search, usable as a citation source in generative search, fresh enough for retrieval, and operable by browser agents.

SearchIndexability, crawl access and stable technical structure.
AI search + citationSnippet eligibility, citation surfaces, direct section links and user-selected sources.
FreshnessAccurate sitemap metadata, feeds and change notification where supported.
Agent webRuntime tools, explicit protocol discovery, evaluations and security evidence.

No ranking promise. ARWP does not claim that a manifest, score, llms.txt, WebMCP, structured data or any other single mechanism raises search ranking. It records upstream requirements and opportunities, then reports what can actually be observed.

Run the audit

The audit combines the existing bounded scanner with the current recommendations registry. It reports failures, warnings, optional opportunities, runtime-only checks and external measurements separately.

arwp audit https://example.com
arwp audit https://example.com --json

Machine-readable registry: registry.json. Canonical packaged copy: GitHub registry.

New directions captured in 2026.09

Google · AI search

Preferred Sources

Detect the official Preferred Sources JavaScript integration, declarative control or content link. Treat it as a user-preference acquisition opportunity, never as a general ranking guarantee.

Google · Citation

Read more deep links

Check for stable heading IDs and flag obvious page-load code that clears URL fragments or forces scroll-to-top behavior.

Freshness

Sitemap lastmod + IndexNow

Observe sitemap freshness metadata and keep IndexNow as an explicit configured/receipt-based mechanism rather than guessing adoption from page markup.

IETF · Work in progress

AIPREF Content-Usage

Observe draft Content-Usage response headers and robots directives, while keeping the mechanism labelled as an Internet-Draft rather than an RFC.

Chrome · Experimental

WebMCP runtime + evals

Static crawling never upgrades a documented WebMCP feature into runtime conformance. Browser evidence and eval receipts remain a separate proof layer.

W3C Community Group

Introduction Layer watch

Track the emerging upstream work and add an adapter when a concrete discovery specification exists instead of starting a competing ARWP manifest.

Measure effects instead of claiming them

Google Search Console generative-AI reporting and Bing Webmaster Tools AI Performance are treated as external owner evidence. Public crawling cannot infer citation counts, grounding queries or AI impressions. ARWP's direction is to compare explicit before/after evidence while preserving negative results.

Status model

pass and fail are reserved for checks with observable evidence. warn identifies heuristics or missed optional opportunities. not-assessed is used for authenticated analytics, content-quality judgement and browser runtime behavior that static HTTP inspection cannot prove. watch is used for upstream incubation.
