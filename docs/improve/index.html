Site Improvement Plan

ARWP combines four evidence streams: Search/AI Growth, grounded Entity Graph remediation, bounded page/link observations and the conditional Search Surface Blueprint. It selects a small ordered backlog without a universal SEO/readiness score or ranking prediction.

Four evidence streams

  1. Growth: current platform guidance, trend radar and measurement-aware hypotheses.
  2. Entity Graph: observed structured entities, missing relations and first-party grounded remediation proposals.
  3. Page graph: canonical/title/H1/lang observations plus sampled internal-link paths and anchor quality.
  4. Search Surface Blueprint: site-kind classification, page-family expectations and newer checks such as host identity, large-image eligibility, publication dates, changelog/release semantics and current Googlebot byte boundaries.

Why another layer?

Audits become less useful when every warning competes equally for attention. The planner caps the default backlog at eight actions and orders them by explicit priority, evidence quality and actionability, while preserving lane diversity across technical Search, entity identity, content semantics, internal links, freshness, visual discovery and product architecture.

Evidence order

  1. Grounded first-party — repository evidence supports a concrete proposal.
  2. Direct observation — the current public page or graph shows the issue.
  3. Source-backed — a current platform recommendation applies.
  4. Manual review / advisory — facts or editorial judgment are missing, or the surface is optional.

No numeric ranking potential is assigned to these classes.

Conditional architecture

The planner does not force every site to create News, Roadmap, FAQ, Dataset or Event pages. Search Surface Blueprint first determines whether a surface is core, recommended, optional or irrelevant for the observed site kind. Thin pages created only to satisfy the checker are explicitly discouraged.

After implementation

Every selected action carries a verification step and a measurement hook. The intended loop is observe → classify → prioritize → review → implement → re-run → measure → keep/revise/revert. Search Console, structured-data checks and AI/referral evidence are measurements, not automatic proof of causality.
