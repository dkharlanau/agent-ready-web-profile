SITE PATTERN GRAPH · v0.1

Turn pattern libraries into evidence about real sites.

A pattern passport says what a practice is. A Site Pattern Map records where it applies, what was actually observed, what remains unknown, what was remediated, and what changed later.

Inspect the example map Read the contract

One chain, four evidence objects

1 · PassportVersioned positive practice or anti-pattern with sources and boundaries.
2 · InstanceBinding to a site, route, route role, template or page type.
3 · ReceiptDeployment-linked proof when a reviewed problem is corrected.
4 · OutcomeLater provider, user or business observations kept separate from implementation proof.
No score. Present, absent, unknown and not-applicable stay separate. A sampled absence never becomes a site-wide certification.

Safe states instead of automated accusations

Heuristic candidate

A detector can nominate a route for review, but its verdict must remain unknown.

Manual anti-pattern review

Catalog entries marked manual-required cannot become present or absent through a string match or automated heuristic.

Deterministic practice evidence

HTTP, markup or workflow facts can support bounded implementation verdicts where the check is actually deterministic.

Outcome observation

Before/after observations are allowed, but v0.1 fixes causalClaim=false unless a stronger future experimental contract is used.

Use it on one site

node bin/arwp-patterns.mjs check .arwp/site-pattern-map.json

node bin/arwp-patterns.mjs actions .arwp/site-pattern-map.json --json

Start with a small set of applicable patterns. Bind them to exact surfaces. Confirm anti-patterns only after reviewing their false-positive boundary. Remediate one bounded problem and attach the deployment receipt.

Then learn across sites

The portfolio view can show which practices are repeatedly applicable but absent, which anti-patterns recur on a site archetype, where owner data keeps conclusions unknown, and which verified changes still lack outcome observations.

node bin/arwp-patterns.mjs portfolio site-a.json site-b.json site-c.json --json

This is prevalence and operational learning, not proof that a common pattern causes rankings, citations, traffic or conversion.

Why this matters

Cite Goose already maintains versioned positive practices and synthetic anti-patterns. The Site Pattern Graph adds the missing site-specific layer, so the project can improve from repeated dogfood instead of merely accumulating recommendations.
