SITE PATTERN GRAPH · v0.1

Turn pattern libraries into evidence about real sites.

A pattern passport says what a practice is. A Site Pattern Map records where it applies, what was actually observed, what remains unknown, what was remediated, and what changed later.

Inspect the example map Read the contract

One chain, four evidence objects

1 · PassportVersioned positive practice or anti-pattern with sources and boundaries.
2 · InstanceBinding to a site, route, route role, template or page type.
3 · ReceiptDeployment-linked proof when a reviewed problem is corrected.
4 · OutcomeLater provider, user or business observations kept separate from implementation proof.
No score. Present, absent, unknown and not-applicable stay separate. A sampled absence never becomes a site-wide certification.

Detector authority is explicit

Heuristic candidate

A heuristic may nominate a route, but its verdict must remain unknown.

Manual anti-pattern review

Manual-required anti-patterns cannot become present or absent through a keyword, timestamp or schema heuristic.

Deterministic evidence

A detector may emit a bounded verdict only when its registered evidence boundary actually supports one.

Authority change is reviewed

A smarter implementation does not silently gain stronger conclusions. Its registry contract must change too.

node bin/arwp-pattern-detectors.mjs list --kind=anti-pattern --authority=candidate

Use it on one site

node bin/arwp-patterns.mjs check .arwp/site-pattern-map.json

node bin/arwp-patterns.mjs actions .arwp/site-pattern-map.json --json

Start with a small set of applicable patterns. Bind them to exact surfaces. Confirm anti-patterns only after reviewing their false-positive boundary. Remediate one bounded problem and attach the deployment receipt.

Then let the portfolio improve the standard

The portfolio view reports prevalence. The Learning Loop goes further: it surfaces repeated evidence gaps, recurring anti-patterns, applicable practices repeatedly absent, measurement debt, applicability-filter candidates and version fragmentation.

node bin/arwp-patterns.mjs learning site-a.json site-b.json site-c.json --min-repeat=2 --json

One site cannot generate a portfolio pattern. Every learning signal remains non-causal: repetition can improve the review system, but it does not reveal a search-engine ranking factor.

Why this matters

Cite Goose already maintains versioned positive practices and synthetic anti-patterns. The Site Pattern Graph turns them into site observations; Detector Authority controls automation; the Learning Loop turns repeated dogfood into reviewed improvements to the standard itself.
