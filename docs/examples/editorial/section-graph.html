An inspectable section graph

Implementation demonstration · noindex. This page demonstrates relationships and source links. It reports no ranking, citation, customer or benchmark outcome. It deliberately omits unknown author and date properties.

A consuming tool can associate each section with the sources used there. The same section locations are available to a person through ordinary links: method and limits.

Connect an article to its visible sections

Schema.org provides a page-element type and a relation for a work's included parts. This example uses a section's fragment URL as its graph identifier. Sources: WebPageElement and hasPart.

Inspect the JSON-LD script in this file. The article references the two section nodes. Each section contains only the sources actually linked in its visible content.

Article → hasPart → section fragment → citation → source URL

To adapt this example, generate the rendered section IDs and graph IDs from your actual section records. Retain visible source links even when a consuming tool reads JSON-LD.

What this graph does not establish

A valid graph describes relationships; it does not prove that a cited source supports every claim. Google says special structured data is not required for generative search. See the AI optimization guide.

Add this optional section graph only for an actual consuming workflow. Measure that workflow's ability to find the right section and source; observe Search or AI outcomes separately.
