# Original evidence: one useful published result

Use this worksheet to *support one existing canonical page*, not to open a second experiment ledger or publish an "AI proof" story. The authoritative experiment, Change Receipt and deployed revision stay in their existing repositories. Store owner-only results privately.

## 1. What the reader needs to decide

- Reader's practical problem: [one sentence in everyday language]
- Existing canonical page/job: [published URL, exact public page identity]
- One useful action they could try after reading: [one action]
- Why a reader would use this instead of a generic summary: [real distinguishing evidence, or mark **not established**]

## 2. Real claim and provenance

| Field | Required observation |
| --- | --- |
| Question | The precise, falsifiable question, not "does AI like this site?" |
| Site/owner permission | Verified published site and right to use the underlying material |
| Frozen experiment | Link the **existing** Controlled Cohort / Growth Experiment ID; do not refreeze it |
| Intervention | One bounded edit/change, with implementation SHA and intended page set |
| Deployment | Independently verified live revision and date, or **not verified** |
| Source | Stable URL, owner capture or publication, with observation date and source class |
| Method | What was done and why the comparator is relevant |
| Baseline | Real observed data before the change, with population/period |
| Control | Comparable unchanged pages or documented reason no comparator exists |
| Outcome | Provider-native measured values **only where available**, otherwise **unknown** |
| Negative result | What stayed flat, worsened, contradicted the claim or could not be verified |
| Alternative cause | Releases, migrations, demand change, coverage gaps or sampling biases |
| Decision | Refer to a separate **reviewed** keep/revise/continue/revert/retire decision, if it exists |

## 3. Publishable text — not a manufactured case study

**The problem.** [Describe what a person actually struggled to do.]

**What we tried.** [Explain one real change to the existing page and why it was worth testing.]

**What we could verify.** [Separate source/build, verified live publication, indexed state, Search/AI exposure, referral, useful action.]

**What remains unclear.** [Missing data, tiny samples, anonymized queries, uncontrolled changes.]

**What happened next.** [Real reviewed decision or "we do not have a decision yet".]

When available, link an authorized reproducible public method and an original asset that genuinely helps the reader decide. Without underlying permission, summarize methodology at the appropriate disclosure level; never expose private Search Console query/page exports, credentials, workplace text or raw user observations.

## 4. Four-role release review

- **Reader:** Does the first paragraph make the choice and practical usefulness clear?
- **Practitioner:** Could another editor repeat the bounded method with their *own* evidence?
- **Skeptic:** Are denominator, chronology, confounders, negative outcomes and provenance explicit? Do not call temporal association causal.
- **Editor/rights:** Do visible prose, titles, snippets, image description and structured data make the *same true claims*, with permission and human review?

## 5. Stop conditions

Do not publish a success story when the publication revision is not independently confirmed, the outcome period predates the intervention, owner data is missing or preliminary, control pages have changed unrecorded, or the example needs fabricated users/metrics. Keep a truthful methodology page or a neutral outcome instead.
