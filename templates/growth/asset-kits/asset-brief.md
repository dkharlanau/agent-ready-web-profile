# One useful asset brief

Template 1.0.0. This is a project editorial workflow, not a ranking requirement.

- Existing intent-owner URL and audience:
- Evidence of the task (reviewed query, recurring issue, user observation; otherwise hypothesis):
- What can a visitor finish in one visit?
- Existing pattern IDs and versions:
- Asset choice: minimal reproduction / comparison input file / decision worksheet / figure with data / maintained reference:
- Why does this improve on the existing page rather than duplicate it?
- Real inputs, versions, assumptions, negative case and expected output:
- Visible explanation available without running code:
- Direct download and stable landing URL:
- Author, actual rights, licensing and permitted reuse:
- How a reviewer can verify the result independently:
- Maintenance owner and change that would invalidate this asset:
- Relevant anti-pattern IDs, including false-positive boundaries:
- Existing BraidGraph node or adoption-record evidence reference:
- Useful next action and observation method:
- Measurement state (unknown until observed):
- Keep/revise/retire criterion:

Review separately: syntax, content correctness, runtime, publication and outcomes. A download click is interest, not proven reuse. Avoid a mandatory email gate for the basic worked example. Do not invent dataset obligations for a site that has no real data.
